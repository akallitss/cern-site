Welcome to the notes hub

How this notes system works: metadata, categories, unlisted pages, and the publish workflow.

How-to 2026-08-16 meta,howto,site

This site is a plain static tree: index.html is the front page, and every HTML file under notes/ is a note. The notes hub is regenerated by scripts/build_hub.py and lists every note with a category, a date and tags.

How a note is described

A handful of <meta> tags in the <head> drive everything. All of them are optional — the builder falls back to <title>, the first paragraph, the folder name, keyword rules and git dates.

tagmeaningfallback
title / <title>Title in the hubfirst <h1>, then filename
descriptionOne-line summaryfirst paragraph, trimmed
categoryGrouping in the hubsub-folder name → keyword rules → Miscellaneous
keywordsComma-separated tagsnone
date / updatedCreated / last editedgit first / last commit, then file mtime
visibilityunlisted hides it from the public hubanything in notes/unlisted/ is unlisted

Categories

Explicit category wins. Otherwise a note in notes/talks/ becomes Talks, and a note straight in notes/ is scored against the keyword lists in site.config.json (Detector R&D, Analysis, Software, Talks & Papers, Meetings, How-to, Personal). Add or edit rules there and rebuild.

Unlisted pages

Files under notes/unlisted/ (or with visibility=unlisted) are deployed to the web server like everything else, but never appear in notes/index.html or the manifest. They only show up in the private hub whose path is set by private_hub in site.config.json. Anyone with the exact URL can still open them — this is unlisted, not authenticated.

Do not put secrets (passwords, tokens, unpublished data you are not allowed to share) in unlisted pages. Obscurity is not access control.

Publishing workflow

# scaffold
python3 scripts/new_note.py "Title" --desc "..." --tags "a,b" [--category X] [--unlisted]
# write the content, then
python3 scripts/build_hub.py      # or: make hub
git add -A && git commit -m "note: Title"
scripts/deploy.sh                 # or: make deploy   (rsync → lxplus EOS)

In Claude Code the /publish-note skill does all of the above from a description of what the note should say.
